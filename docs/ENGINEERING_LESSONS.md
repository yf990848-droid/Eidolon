# 纸境工程问题与经验记录

> 用途：持续记录纸境在开发过程中遇到的问题、诊断过程、优化决策与工程经验，便于项目复盘和面试说明。

## 记录原则

- 先记录现象与证据，再判断原因。
- 区分临时诊断措施与正式修复，避免把猜测写成结论。
- 不在文档、日志或代码中记录 API Key、用户原文等敏感信息。
- 每个问题保留“现象—原因—方案—验证—经验”的完整链路。

## 案例一：DeepSeek 偶发未返回正文

### 问题现象

调用 `/api/agent` 时，部分请求返回 `200`，部分请求等待约 20 秒后返回 `502`，前端提示“DeepSeek 未返回内容”。

### 原因分析

DeepSeek 响应不仅包含正文，还可能通过 `finish_reason` 表示长度上限、内容过滤或服务资源不足。原实现只检查正文是否为空，把不同失败原因统一处理成“未返回内容”，导致信息不足。

### 已完成优化

- 解析 `finish_reason`，区分长度上限、内容过滤和服务资源不足。
- 显式关闭不需要的思考模式，避免正文任务只返回推理内容而没有最终正文。
- 保持 API Key 仅存在于服务端环境变量中。

### 经验总结

第三方模型调用不能只判断 HTTP 状态码。还应检查业务响应结构、结束原因和实际内容，并向用户返回可行动的错误信息。

## 案例二：文风分析结果被判定为不完整

### 问题现象

DeepSeek 请求成功且返回合法 JSON，但页面提示“文风分析结果不完整，请重新分析”。

### 当前证据

- 前端要求 `summary`、`writingInstruction` 和七项 `features` 全部存在且非空。
- 服务端只要求模型返回 JSON 对象，没有对字段结构进行标准化。
- JSON 模式保证语法合法，但不能保证字段名称和内容完整。
- Mock Provider 返回固定完整结构，能够通过当前校验；问题集中在真实模型输出的结构波动。

### 本次诊断优化

暂不修改提示词或兼容规则，先增加结构化日志：

- 为每次 Agent 请求生成 `requestId`。
- 记录任务、模型、耗时、Token 用量和输入长度。
- 文风分析只记录顶层字段名、特征字段名、缺失字段和响应长度。
- JSON 解析失败时记录错误类型，不默认记录原始响应。
- 仅允许在本地显式设置 `AGENT_LOG_RAW_RESPONSE=true` 时打印原始模型响应。

### 预期验证

重新执行一次真实文风分析后，在运行终端查找：

```text
"event":"agent.style.response_shape"
```

重点查看 `missingFields`、`topLevelKeys` 和 `featureKeys`。根据真实返回决定采用字段别名兼容、缺失项兜底还是提示词强化。

### 经验总结

- 生成式模型的“合法 JSON”不等于“符合业务 Schema”。
- 在修改 Prompt 或解析逻辑前，应先建立可观测性，避免凭猜测修复。
- 日志应优先记录结构与元数据；原始文本只作为本地、短时、显式开启的诊断手段。
- 请求 ID 能把浏览器错误、服务端日志和模型调用串联起来，显著降低排障成本。

## 面试表达参考

可以按照 STAR 方法介绍本次实践：

- **背景（Situation）**：文风分析接入真实大模型后，HTTP 请求成功但业务校验偶发失败，前端只有笼统提示。
- **任务（Task）**：在保护用户文本和 API Key 的前提下，定位模型输出与业务 Schema 的具体差异。
- **行动（Action）**：设计轻量结构化日志，引入请求 ID，分层记录请求结果、JSON 解析和字段完整性，并为原始响应设置仅限本地的显式开关。
- **结果（Result）**：当前已具备精确诊断能力；完成真实调用后，再补充实际缺失字段、最终修复和验证结果。

## 案例三：篇幅参数没有驱动创作流程

### 问题现象

页面允许选择短篇、中篇和长篇，但三种选项都执行“创意方案—大纲—第一章—逐章保存”的相同流程。篇幅只进入模型输入，没有影响页面阶段、生成任务和保存行为。

### 根因

最初实现只有一套固定的 `Stage` 状态机；`length` 是提示词参数，不是业务流程的分支条件。因此模型知道篇幅，产品流程却没有体现篇幅差异。

### 最小优化

- 短篇确认大纲后调用独立任务，一次生成完整正文，并以单个“全文”章节保存。
- 中篇确认大纲和章节数后逐章生成，不额外增加细纲步骤。
- 长篇先生成与总章数一致的结构化章节细纲，用户确认后再逐章生成。
- 复用现有 `chapters`、书架、阅读和下载结构，只增加可选的章节数与章节细纲字段。
- 旧作品缺少新增字段时使用默认值，避免一次性迁移浏览器数据。

### 经验总结

- 产品选项不仅要进入 Prompt，还必须驱动状态机、交互步骤和数据模型。
- 不同流程应共享保存和阅读等稳定能力，只在真正有差异的生成阶段分支。
- 为本地持久化对象增加可选字段，是早期产品兼容旧数据的低成本方式。
